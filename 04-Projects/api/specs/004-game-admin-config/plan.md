## Summary

Game Admin (Caro) can create, update, deactivate, and reactivate game configurations
(board size × move time presets). Players browse the active configuration list when
creating a new game. All configuration records are soft-deleted (never physically removed),
audit-tracked with who created/deactivated them, and protected by a dedicated JWT-claim
guard (`GameAdminCaroGuard`). A partial unique index enforces at most one active config
per `(boardSize, moveTime)` combination, atomically preventing duplicates.

## Key Risks & Mitigations

| Risk | Mitigation |
|---|---|
| `gameAdminRoles` JWT change affects existing tokens | Non-breaking: no existing guard reads `gameAdminRoles`. Tokens with UUID values produce an empty role check (no crash). Users re-login after deploy to get slug-based tokens. |
| Partial unique index race condition | DB-level index is atomic; no application-level locking needed. |
| Caro game seed conflicts with existing `platform.games` rows | `ON CONFLICT (slug) DO NOTHING` — idempotent migration. |
| `createdBy` / `deactivatedBy` referential integrity | Acceptable: audit fields reference stable account IDs from JWT `sub`. Account deletion is out of scope for this feature. |
